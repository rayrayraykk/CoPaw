# RestoreFiles：独立替换与清理保护

日期：2026-09-14，macOS ARM64。证据目录：`dist/qa-restore-identity-20260914-hGOALi`。承接 [宿主恢复所有权](agent-publication-recovery-acceptance.md) 和 [实施清单](../architecture/channel-profile-authority.md)。本节不是完整事务恢复或发布验收。

## 复现与实现

首轮 `identity-red` 四项真实执行全部失败：回滚接受了外部替换/原地编辑的目标；提交清理删除了暂存目录新增的独立文件；父目录被另一个普通目录替换后，路径相同导致清理访问了新目录。测试仅操作新建临时夹具，没有使用用户数据。

共享 `RestoreFiles` 现记录原目标、替换树、父目录与暂存目录的身份。使用已锁定的 cap-std/cap-fs-ext 取得跨平台身份，文件按固定大小缓冲计算 SHA-256；目录记录原生文件名映射、权限及递归内容，链接只记录链接值，不读取指向的外部内容。新增、删除、同字节的不同文件、原地改写和权限变化都不以“路径仍相同”视为原事务数据。捕获过程中检查打开对象及读取前后的状态，不新增产品依赖。

发布前核对原目标；回滚前核对原始备份和已安装的替换树，暂存回滚落点被占用时不覆盖。失败对象保留，其他可恢复条目继续按原机制恢复；只有原替换对象重新回到目标位置时才允许对应逆操作继续。

Drop 和提交清理只接受已知、未改变的暂存内容；未知条目或目录/树发生独立变化时保留整个恢复目录。暂存构建未成功加入事务时也由 `Swap` 的同一清理检查处理。新建目录的非递归清理增加身份检查，不删除已被另一个目录替换的路径。

## 仍未完成

- 这是可观察独立变化的顺序保护，不是所有路径操作的原子比较交换。检查与 rename/递归清理之间的恶意并发竞态仍需能力目录/原子操作专项；不能据此关闭全部外部替换风险。
- 不保证无权限读取、特殊文件或活跃变化的目录可被覆盖：无法完成身份/内容核对时拒绝继续并保留数据。目录扫描和摘要有额外 I/O，尚未完成大型真实 Workspace 性能验收。
- 持久日志、凭据旧值的强杀/重启恢复、panic 和全体在途任务屏障仍未完成。父目录被挪走时保留数据不等于自动发现新位置。
- 当前仅在 macOS ARM64 实机执行；采用现有跨平台依赖不等于 Windows/Linux/macOS x64 运行已验证。

本轮原 Console 源码与浏览器脚本未改，原 Anthropic 输入焦点及 SDK EOF 间歇失败继续保留。尚未重建 release Core 或九类安装包；`eaTvv4` 不包含本轮改动，没有执行包内 Core 或原生 Desktop/VS Code 激活。
