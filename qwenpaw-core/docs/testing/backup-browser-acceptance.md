# 原 Backups 页面浏览器验收

本门禁使用未修改的 `console/src` 生产构建、真实 Chrome 和 Rust HTTP 服务。数据库、工作目录、两套备份签名密钥和全部业务凭据均在测试 fixture 中创建；不访问用户数据或真实系统钥匙串。Chrome 使用临时 profile，导出的 ZIP 仅保存在该 profile 的临时下载目录。

## 执行

要求 Node 24+、Chrome/Chromium、Rust。`node` 必须在 PATH 中；Chrome 非默认安装位置时设置 `QWENPAW_CHROME`。

```sh
# 在仓库根目录构建原 Console
npm --prefix console run build

# 在 qwenpaw-core 目录显式运行浏览器门禁
cargo test -p qwenpaw-app-server original_backups_browser_ \
  --all-features -- --ignored --nocapture
```

两个用例因依赖浏览器和已构建的前端而不在默认 Rust 单测中执行，发布前必须单独执行；不能把默认单测中的 ignored 当成浏览器验证通过。

## 覆盖范围

- 原 24 个导航页渲染、API 错误及浏览器异常检查。
- 原 Backups 控件创建备份，列表显示并经刷新保留。
- 独立在途任务用例：fixture 暂时持有检查点锁，使真实备份等待；页面刷新后自动重开进度弹窗并通过 SSE 观察同一个 job，不能再次 POST 创建。原取消按钮调用实际 API，fixture 观察取消信号后释放锁；验证终态、空列表、无残留 ZIP 及下一次原 UI 创建成功。不增加生产控制接口，不依赖大文件压缩速度或修改前端。
- 原导出警告确认、真实 ZIP 下载和文件签名头检查。
- 将下载的文件交给原 Import 输入框，验证同 ID 冲突确认与覆盖。
- 从原恢复流程选择先自动备份，等待该备份落盘，再确认恢复；不仅断言成功提示，还核对实际 Workspace 文件内容。
- 原搜索和单项删除，保留自动创建的恢复前备份。
- 导入另一套独立签名密钥生成的归档，未确认信任时不能发布；确认后检查 `accepted_via_trust` 持久化。
- 从异机归档选择不先备份、直接恢复；检查默认选中保留本机安全/MCP 配置，并再次核对实际文件。
- 按顺序检查导入响应为冲突 409、确认后 200、信任拒绝 400、确认后 200；其余场景内 API 失败均视为失败，不因同 URL 后续成功而忽略。

## 不代表已验收的范围

此门禁不代替多 Agent 全部 scope 组合、活跃本地模型停启、断电恢复、移动端交互、Windows/Linux 原生安装态或 9 个最终发布产物验证。上述项目继续由主计划 checklist 跟踪。

## 本机执行记录

2026-09-09：24 个导航页和上述 Backups 本机/异机往返均通过，无浏览器异常或非预期 API 失败。测试最初发现异机恢复默认保留安全配置时的持久化格式错误；修复 Core 版本化编码后通过。异步详情加载和列表刷新期间，脚本等待原控件可见且可用后再点击，不改动前端行为。

同日新增在途刷新/取消门禁通过：确认刷新切换到新 Document、原进度条可见、SSE 至少连接两次且只有一次创建请求；取消后 job 为 cancelled、result 为空、没有 active job 或归档，随后创建的唯一 ZIP 在 fixture 文件系统中存在，原工作区内容不变。该独立用例约 13 秒，不改变原 24 页门禁的覆盖范围。
