## 本次范围

原生 Agent 注册表 v2 区分可复用的对外 Agent ID 与内部 Workspace 数据标识，删除注册保留规范路径索引。创建、复制、恢复规划选择本机绑定；原 API 创建/配置响应不暴露内部字段。已有原生 v1 活跃注册项可确定性补足 `legacy_agent` 命名空间，不能因新注册项复用 ID 就再次领取历史标识。没有读取 Python jobs.json/chats.json 或迁移旧产品数据。

实际 HTTP 定向组共 9 项：

- 同 ID/原目录复用、同 ID/新目录隔离、原目录/新 ID 接回、重开后稳定以及复制获得新标识；断言原创建响应完整结构。
- 自动与自定义目录由注册入口重新创建时分配新标识；测试只移动临时目录，不删除保留文件。
- v1 注册删除前补足索引，后续同名新目录不领取旧标识，旧目录换 ID 仍获得历史标识。
- Unix 符号链接规范化后接回同一绑定。
- v2 缺失/冒用/未索引/非法 UUID、携带新绑定的 v1 和未知版本拒绝读取，原注册表字节保持。
- 原 4 项创建失败清理回归：新自动目录清理、已有自动目录与配置保留、自定义目录保留、已有自动符号链接目标保留。

首轮 App Server 回归中，恢复测试夹具在手动移动注册目录时没有同步新增的索引，导致校验拒绝该夹具。同步夹具的目录绑定后，保留原来的“移除注册不授权覆盖未选中 Agent 目录”断言；不是把越界恢复放行。恢复原有完整注册表结构断言继续覆盖选中绑定和未选中索引的保留。
