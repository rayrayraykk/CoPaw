# Agent 组合发布：宿主恢复所有权与准入

日期：2026-09-14；macOS ARM64。证据目录：`dist/qa-publication-recovery-20260914-9pAOK0`。承接 [普通回滚验收](channel-profile-publication-acceptance.md) 与 [实施清单](../architecture/channel-profile-authority.md)，不是全功能或发布验收。

## 已实现范围

- 发布失败且逆操作继续失败时，宿主保留 `RestoreFiles` 和尚未恢复的凭据原值。原值缺失单独表示，已完成的凭据逆操作从待恢复对象移除，不重复执行。凭据原值只驻留内存，没有写入普通 JSON、日志或新钥匙串账户。
- 原 18 个普通 Agent 锁入口共用带恢复状态检查的锁；Profile 更新在原 Agent 锁内先恢复，再解析当前注册表并执行新的发布。恢复继续失败返回 409，不能用另一个 Agent 的提交覆盖旧逆操作。
- Channels 读取权威数据时再次检查状态；默认 Workspace 身份、运行上下文和备份快照入口也拒绝使用待恢复数据。HTTP 业务入口、协议准入及备份恢复入口拒绝新工作；备份取得 Core 独占屏障后再次检查，避免在排空期间出现的新失败被遗漏。
- 健康检查和认证关闭端点仍可到达；`readyz` 在待恢复时返回 503。普通 Agent PUT 可进入原处理器重试恢复；恢复成功后才执行新请求，不更改正常请求的返回结构。
- 正常关机在现有服务排空之后再重试，继续失败时保持宿主内的恢复对象；成功后不重新开放已关闭的协议服务。

## 回归与失败记录

新增四项回归：

1. 原凭据存在/不存在两种情况；注入“先写入再报错”与持续拒绝回滚；验证完整文件/注册表/SQLite 快照、新 Profile/其他 Agent/Channels/删除/读取拒绝，以及恢复后完整 Profile。
2. 完整 HTTP 路由栈和直接备份路由的门禁、健康与 readiness、未认证关闭、协议拒绝、普通 PUT 恢复。这里是 Axum/Tower 路由测试，不宣称真实 TCP 或浏览器操作。
3. 正常关机期间持续失败、第二次恢复成功、第三次不重复写凭据；协议始终保持关闭。
4. 独立暂存/交换文件后暂移目标父目录，三次文件逆操作失败时保留对象；凭据只恢复一次，目录恢复可达后取回原始字节并清理本事务的暂存目录。仅覆盖父目录暂时不可达，不代证所有外部文件替换情形。
