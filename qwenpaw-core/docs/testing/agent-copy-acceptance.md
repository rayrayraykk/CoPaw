# 原生 Agent Copy 验收

日期：2026-09-09。对应计划 §41。仅接通任务复制数据路径，不代表非默认任务执行或所有功能完成。

## 实现与原交互

原 Python 复制 jobs.json 中的规格，不复制独立 jobs_history，返回后才异步启动 Agent。Rust 现在从唯一权威 SQLite 复制相同规格和 enabled、保留对外 ID，重新分配内部键和归属；不复制状态、游标、历史、in-flight 或 run claim，不提前生成调度状态。不再生成或复制非权威 jobs.json；未勾选 copy_jobs 时不读取 Cron 数据，原默认值仍为 false。

锁顺序为 Cron → Agent。名称、源路径、任务结构与容量在创建目录前验证；新目录使用 create_dir，不覆盖或清理已存在的未注册目录。任务写入先于 Agent 索引发布，发布失败回滚原始 Cron 字符串；准备/数据库失败清理本次新资源。回滚或清理失败明确报错，保留需要恢复的目录/凭据。没有实现跨 SQLite、文件、凭据存储的进程崩溃事务，不能宣称 crash-atomic。

顺便修复直接阻碍连续复制的问题：原自动 ID 取 UUID v7 前六位时间戳，前缀被占用后长时间循环；改取末六位随机部分，继续检查目录索引碰撞，保持原六字符 ID 形状。

## 测试证据

先补 HTTP 回归，在旧实现实际失败：复制返回成功但任务数量为 1，预期为 2。随后实现，九项后端回归通过（0.19 秒），覆盖完整规格/启用状态、真实工具产生的历史不复制、连续三次复制、其他 Agent 完整数据不变、重开、未勾选且 Cron/旧文件损坏、空任务不创建设置、名称/结构/容量拒绝，以及真实数据库、索引发布、凭据、回滚失败注入。故障只在临时 fixture 数据库/目录和内存凭据接口制造，无日常 keychain 或生产 key 操作。

原浏览器复制弹窗独立 1/1 通过（13.65 秒）：验证全部四个原默认复选框，分别通过原按钮提交未勾选和勾选任务的复制，刷新后两个 Agent 都保留；Rust 断言只有勾选者拥有原生复制任务，完整其他数据不变，Core 重开后结构一致。浏览器 fetch 仅用于读取验证，不代替提交操作。没有修改 console/src。

测试开发中修正了导入/序列化比较问题（内部缓存需重新读取、空映射按原 serde 省略），也按严格 Clippy 拆分名称校验和清理逻辑；没有放宽原任务契约或关闭检查。随后新增第十项真实活动任务回归：复制不能等待、复制或中断源任务的活动声明，停机只收束原任务，副本没有运行状态或历史。该测试初次清理只等待而未发送 shutdown，虽通过但等待了模型超时；已改为显式取消并用 5 秒超时验证排空，不修改产品超时策略。
