# Backend Debug 日志验收

日期：2026-09-10。对应 [设计与 checklist](../architecture/backend-debug-logs.md)。
只使用临时数据、回环服务、虚构密钥/内存凭据及独立 Chrome profile；
没有改动 `console/src`，没有执行分发包里的 Core，也没有访问系统剪贴板。

## 初始失败与修复

- 原占位接口使 5 项读取回归全部失败；实现后普通 API 测试 5/5 通过。
- 使用固定、可精确表示的文件时间戳断言完整 JSON，避免测试自身的浮点
  序列化舍入差异。生产日志时间戳仍来自文件元数据。
- 隔离执行原 Python 路由 AST，而非重写参考实现；不加载旧产品初始化。
  完整 HTTP 状态与 JSON 对照发现 `20.0`、`1_000` 和超大整数错误类型的
  差异，修复后含重复参数、空参数及非法数值的 28 个请求全部相等。
  API 加参考组 **6/6，0.49 秒**。
- 文件写入专项 **7/7**：追加、重新打开、大小轮转/备份保留、0 备份、
  轮转失败仍写当前记录、多线程完整记录，以及 Unix 符号链接拒绝/0600 权限。
- 真实 Desktop CLI 初测暴露 macOS `/var` 与 `/private/var` 的路径别名差异，
  已将日志快照路径对齐原后端的解析路径；最终 CLI 回归通过。
- 完整 HTTP 回归另发现原 bootstrap 测试仍期待旧占位的空路径/0 行。
  已改为原契约的完整 JSON 和“不创建文件”断言，未删除断言或放宽检查。

## 真实 tracing 与原页面

生产 CLI 格式保留时间、target、嵌套 span 与记录字段，输出纯文本 WARNING。
两项格式测试通过。stderr 与文件双写在 Workspace 初始化成功后接入；
纯协议宿主尚无 Workspace 的现有架构缺口不在这里伪装为已解决。

原 Console `/debug` 浏览器专项 **1/1，15.85 秒**：使用生产 formatter 和
`BackendLog` 生成真实 DEBUG/INFO/WARNING/ERROR 事件，经真实 Rust HTTP API
进入未修改的原页面。追加事件由另一个仅测试存在的回环控制服务触发，
没有拦截或替换 Console 的 API 响应。验证：

- 日志路径和默认倒序；四种级别逐个筛选及恢复 All；
- 大小写不敏感搜索和原页面高亮；清空后完整恢复；
- 切换正序，逐行顺序与实际事件顺序一致；
- 原 3 秒自动刷新读到追加日志，暂停后超过一轮不出现新记录；
- 手动刷新读到暂停期间的新记录；
- 点击原复制按钮，捕获 `clipboard.writeText` 的完整已过滤文本。
  这不证明 OS 剪贴板或 WKWebView 原生权限集成。
