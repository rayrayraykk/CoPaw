# Agent 组合发布：文件日志与可信控制记录验收

日期：2026-09-15，macOS ARM64。证据目录：`dist/qa-publication-files-20260915-3pNZ7P`。承接 [恢复协议](../architecture/agent-publication-journal.md)。本轮是 Rust 库组件及隔离进程组合验收，不是实际 App Server 启动恢复，也不是完整 goal 或安装包发布通过。

## 实现

`AgentPublicationFiles` 只处理 `agent.json` 与 `catalog.json` 两个普通文件。暂存复用现有 RestoreFiles，记录父目录、恢复目录、原/新文件身份、权限和 SHA-256；目录/链接不能作为这两份配置的内容。日志含安装 UUID、事务 UUID、Agent ID 及原生路径编码，保留原文件缺失语义，不保存文件正文或凭据。它是可信宿主调用的 Rust 接口，不是新的 HTTP/SDK 远程方法。

暂存文件和目录同步后，使用私有临时文件同步日志并通过不覆盖写入发布；日志最多 128 KiB。对象未成功持久化日志时拒绝 apply。重开不跟随日志链接，必须核对外围可信 SHA-256、安装/事务与 catalog 路径，才接受严格结构的记录。宿主必须先在可信控制存储保存摘要，不能从日志旁的任意 sidecar 读取一个摘要就视作可信。

回滚根据目标、暂存原值、暂存替换值的实际位置判断，而非序列化内存布尔标志。目标是自己的替换文件才移回暂存；自己的原值尚在暂存且目标缺失时才移回原位。各条目独立尝试，遇到外部改写继续保留。清理核对 prepared 已回滚或 committed 已发布状态，只删除已知、未变的普通文件，非递归移除空恢复目录；部分清理、整目录已清理可重试。对象 Drop 不自动丢弃恢复数据。

Storage 新增安装级 `core_installation` 和 `agent_publication_journal`：稳定 UUID 不随普通重开或逻辑恢复改变；32 字节日志摘要与 prepared 记录同事务预留。摘要按判定槽位外键级联清除，错误 ID/状态不能清除；摘要写入失败不留下半个 prepared，摘要清理触发错误则判定和摘要一起保留。两表不进入逻辑备份，孤立摘要阻止新预留与业务表替换。Core 新写接口遵守恢复锁。

## 验证范围

首轮 `files-targeted` 8 通过、1 失败，失败在本机文件系统拒绝创建非法 UTF-8 名称，尚未进入恢复逻辑。保留原日志，改为本机 Unicode 目录的真实恢复测试，并新增非法 Unix 路径字节的纯编码往返；不宣称 macOS 文件系统接受非法 UTF-8 名称。Linux 非 Unicode 实际文件和 Windows 路径/持久化运行未验证。

10 个文件组件测试覆盖每个正向 rename 边界的重开（原文件存在/缺失）、提交后保留新值、反向交换中断和部分清理、同字节不同文件身份、原地改写、未知暂存条目、父目录/恢复目录独立替换、摘要篡改、外国安装/事务/catalog、禁止日志覆盖、Unicode 实际路径、链接拒绝和原生字节编码。另有 4 个 Storage 和 1 个 Core 测试覆盖稳定安装、可信摘要原子性、删除失败回滚、孤立摘要保留和恢复锁。

隔离进程测试通过 `current_exe()` 启动本次单元测试二进制，仅使用新建临时目录。在 prepared 后、四次 rename 后、committed 后及首次暂存清理后共 7 个边界，确认子进程到达同步标记后强杀并 wait 回收。父进程重开 SQLite，以数据库中的安装 ID、判定和摘要读取日志：prepared 恢复完整旧文件且 Channels 未变，committed 保留完整新文件及新 Channels。清理重复运行后精确清除判定。测试未使用包内 Core、真实 App Server 启动入口、真实凭据或系统 Keychain。

新增共 17 个测试入口：10 个文件测试、1 个强杀矩阵、1 个其使用的子进程入口、4 个 Storage、1 个 Core；子进程入口在普通父进程测试中无环境参数时直接返回，不把它计作额外功能覆盖。`publication-targeted` 61/61 包括既有发布相关回归，随后补充 Agent ID 绑定再执行完整工作区。

最终 `workspace-final` **829 通过、0 失败、31 显式项忽略**，111.15 秒，退出 0，新增入口及强杀矩阵均进入完整运行。`clippy-final` 全工作区/全目标警告即错误通过，`fmt-check` 通过。首次 Clippy 指出的导入位置、通配导入和公开函数直接 unwrap 已修正，没有关闭 lint。

原页面专项顺序 **6/6**：Agents 3 项（32.76 秒）、Channels 1 项（11.60 秒）、备份 2 项（76.68 秒），三条命令均退出 0。覆盖原页面配置与重开、普通 Chat/Cron 停止、Channels 抽屉隔离及备份活动刷新/取消/完整往返；本轮未重跑其余 25 个显式项。

`verify.mjs` 核对整组、17 个新增入口、强杀矩阵、6 项原页面及严格检查终态，保留首轮文件系统能力失败和 Clippy 失败记录，链式校验上一阶段证据、2,906 条来源与九个旧制品哈希。`verification.json` 保存当前文件哈希，并显式区分库组件强杀通过和真实宿主/凭据强杀尚未验证。

## 仍未完成

- 真实 Profile、启动前恢复和凭据账户尚未与文件对象接通；当前启动仍按原有内存恢复路径工作。七边界测试不是完整应用恢复证明。
- 文件对象不删除持久日志或 SQLite 判定。外围日志/凭据/判定收尾、prepared 之前的孤立暂存、凭据清理中断、崩溃时全部在途操作与 panic 行为仍需完整终结协议及测试。
- 核对与 rename/remove 之间的恶意并发竞态不是原子 CAS，现有保护只拒绝观察到的独立变化。未验证断电、真实 OS 凭据持久性、Windows 目录同步、Linux/macOS x64 或大型 Workspace 性能。
- 原 Console 与浏览器脚本未改，release Core 与旧九类 `eaTvv4` 制品未重建；没有运行包内 Core、原生 Desktop 或 VS Code 激活。既有焦点/SDK EOF 间歇问题继续保留。
