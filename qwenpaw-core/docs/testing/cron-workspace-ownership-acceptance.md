# Cron Workspace 持久化归属验收

日期：2026-09-09；计划 §14.2.24.48。实现边界和图见 [Workspace 数据身份](../architecture/workspace-data-identity.md)。

## 已实现行为

原生 Cron v4 将 Job 内部键绑定到类型化 Workspace 标识；公开任务 ID 在数据标识内唯一，旧 Agent 来源字符串不能授权读取、复制或执行。入队从数据标识找到当前注册并核对目录，声明/LiveLease 保存固定归属和发生时 Agent ID，完成不回查可复用的公开名称。原目录换 ID 后任务及历史保留，新目录复用旧名称不取得任务；旧 Inbox 历史事件不重写，新事件使用实际运行时身份。

旧原生格式默认任务可绑定不可删除的默认注册；非默认任务只有历史 `legacy_agent` 绑定可以接回，当前同名 UUID 注册不足以证明归属。不能判定的任务保留，不自动迁给新注册，不读取 Python 文件。

Agent 归档快照为 v2，显式携带来源绑定；只包含公共引用的全局注册表仍为 v1。范围导出按 Workspace 标识选择；恢复映射到规划目标，内部键冲突时联动重键，未选中任务、游标、历史和声明保留。任务声明不能与未选中的 Inbox run/trace ID 冲突，即使归档没有对应 Inbox trace。

## 测试范围与修正记录

- 真实注册/任务执行链：Writer 运行、删除、原目录注册 Editor、另建同名 Writer、Core 重开、Editor 再运行与复制、同名新目录复制为空、重新启用仅重建对应游标。真实文件效果、任务历史和 Inbox 新旧身份均验证。
- 真实旧原生格式：有 v1 历史注册依据时执行并发布 v4；没有历史依据的同名 UUID 注册在入队前被拒绝，原任务存储原字节保持。
- 逻辑格式与备份：同公开名称/公开任务 ID 在不同 Workspace 下共存；缺失、未知、非法和重复绑定及错误声明拒绝；重新注册后的导出、跨目标映射、Job/claim 重键、未选中完整结构和运行 ID 冲突验证。
- 实际两套 Core 的 HTTP 备份/恢复：源、目标 Writer 使用不同 UUID，恢复后任务绑定到目标 UUID，未选中的默认任务完整结构保留，源数据不变。
- 切换初轮出现全局引用快照误用 v2 的生产错误，导致恢复请求被拒绝；已将其保持在独立的 v1 格式。没有放宽归档格式验证。
- 原测试中手工构造的当前任务改为显式 Workspace 绑定，专门的旧格式测试继续保留。复制/删除/恢复仍断言完整数据结构，包括新增绑定，未删除原状态、历史和回滚断言。空用户目录测试保留 Core 标识，归档文件集合仍不包含标识。
- 关闭或已无注册的任务在入队前直接拒绝，不再先创建一条伪造的失败运行；对应测试验证完整 Core 快照不变、无模型调用和无 LiveRun。入队后关闭/删除的取消、排空和记录语义保持。
