# 邮件 ACL 命名空间验收

日期：2026-09-09；计划 §14.2.24.52。该记录不是邮件监听、全部功能或安装态完成声明。

## 范围

沿用原邮件路由和存储的 `(Workspace, Agent ID)` 权限身份。内部 v2 使用类型化 Workspace 标识；原页面 API 不增加内部标识，`console/src` 不修改。汇总与广播只选启用且开启邮件推送和 ACL 的注册；直接修改仍允许已注册但禁用/关闭邮件的 Agent。未知批量目标跳过且不创建或升级存储。

范围备份保存选中 Workspace 内所有历史 Agent 权限主体，恢复只重映射 Workspace 标识，不改写内部名称。旧原生 v1 的非默认主体留在历史命名空间，不被同名新 UUID 注册认领；不读取或迁移旧 Python 数据。

## 测试与失败记录

- 原 Python 邮件路由与存储参考基线 **39/39**（0.86 秒），临时路径三种身份变化完整结构比较通过，详见 [设计](../architecture/mail-access-control-identity.md)。未使用真实邮箱或凭据。
- Rust 初次定向 **6/6**，补充纯存储验证后 **9/9**（0.25 秒）。覆盖开关、广播/直接写、空元数据、换名/名称复用/重开、旧格式、完整 Workspace 备份与冲突、非法版本/重复标识/错误主体。
- 更新旧备份测试夹具为明确绑定的 v2；HTTP 汇总测试通过原 Agent 配置接口显式开启邮件功能，未更改产品默认配置或削弱汇总开关。
- 新增多 Agent 审批/拒绝/忽略、备注、耐久 replay 和空目标无写入测试。首次完整工作区在 App Server 为 **327 通过、1 失败、17 忽略**（8.39 秒）；失败是新夹具整数时间戳与既有浮点输出不一致，修正夹具保留完整结构断言。该次没有继续完成其余工作区测试。
- 同次真实跨 Core HTTP 范围恢复通过：来源包含当前 writer 与历史 editor 两个内部主体；验证目标 Workspace 映射、未选中 default 完整保留、来源不变及 SQLite 重开。
- 检查原 Python 稳定排序后，新增相同时间戳用例实际复现 Rust 按 Agent 名称重排：**0/1**（0.10 秒）。已将可见 ACL 中间集合保留注册顺序，仅对象响应转为映射；pending 排序继续按时间降序，平局保留原顺序。修复结果待下方完整复验。
- 严格 Clippy 首次失败为两处测试函数超过 100 行及一次可能截断的测试索引转换；按夹具/失败批次职责提取函数并改为检查转换，没有禁用 lint。
- 邮件抽屉专项首次编译需要显式导入断言宏；首次运行超过原 90 秒限制且无完整报告，保留为失败，未延长超时。后续两次完整报告分别定位驱动的默认 `ant-` 前缀不匹配应用的 `qwenpaw-` 前缀，以及把行首复制按钮当成删除按钮；修正驱动定位，不改组件和 API。第四次运行 **1/1**（13.55 秒）通过：批准 writer、拒绝 reader、忽略另一条待审、原输入框广播添加带元数据的域白名单、按 writer 筛选并只删除其记录、刷新核对两类名单、完整存储比较和 SQLite 重开。关闭邮件的 off 主体完整不变，writer replay 耐久保留，未调用模型或伪称处理了邮件。
