# 原官方插件目录

延续原功能、原前端等价方案，补齐 `GET /api/plugins/catalog`。该读取入口独立于尚待确认的插件安装/后端执行路线；不修改 D3，不把目录可浏览当作 Python 插件原包可运行。

## 契约与实现

固定下载 CDN：先取 `/metadata/index.json`，再取 `products.plugins.index_url`。返回原 `{updated_at, plugins, error}`，保留主索引失败、非法路径、插件索引失败的原 HTTP 200/error 响应。支持 gzip header/magic；请求和解压后各有 8 MiB 边界、每次请求 30 秒上限；不转发客户端凭据，不跟随重定向，后续 URL 必须保持固定来源。上游不可信内容不能扩展成任意代理。

按原规则推导 plugin_id、字段本地化与排序；从当前 Rust 数据目录内磁盘 manifest 读取已安装版本。不能复用仅接受有效前端入口的列表过滤器，否则纯后端或旧 manifest 的安装标记会错误。沿用目录/文件路径边界，跳过越界符号链接和超大 manifest，不读取日常 Python 数据。

版本比较保留 PEP 440 排序、非法版本字符串回退；运行产品预发布按 base release 判断最低要求，暂不执行原代码已禁用的 max 上界，但仍验证 max 和结构化字段。新增锁定的纯 Rust `pep440_rs` 依赖，不启用 Python bindings，不自行用 SemVer 替代。参考 [解析库文档](https://docs.rs/pep440_rs/0.7.3/pep440_rs/) 和 [版本排序 API](https://docs.rs/pep440_rs/0.7.3/pep440_rs/struct.Version.html)；实际兼容性以原 handler/packaging 对照为准。先获取该公开依赖、审查锁文件差异，此后测试保持离线锁定。
