## 架构与代码入口

总体设计见 [system-overview](../architecture/system-overview.md)、[app-protocol](../architecture/app-protocol.md) 和 [主计划/checklist](../plans/rust-core-refactor-plan.md)。Harness 当前边界见 [harness-runtime-parity](../architecture/harness-runtime-parity.md)。

```text
原 Web UI / Desktop / VS Code / CLI / TUI / 远程客户端
       │ HTTP 兼容接口或 app-server 协议（各入口完成度见主计划）
       │ Rust / Python / TypeScript 客户端 SDK
       ▼
Rust qwenpaw-app-server → qwenpaw-core / storage / MCP
       │
       └─ Harness HTTP/Agent 接线：尚未完成，不能视为已启用
                       ▼
              qwenpaw-harness（已实现独立底层组件）
              CodexProvider → runtime pool → sessions → raw turn
                       │ JSON-RPC / 子进程生命周期
                       ▼
                外部 Codex app-server
```

SDK 是客户端层，不是 Python 内核回退。当前 Rust Harness 不依赖 Python 产品运行时；部分对照测试和 MCP 子进程 fixture 使用 Python。Qoder 原生执行链尚未实现，Claude 的 coming-soon 元数据也不能当作执行支持。

主要入口（均相对 `qwenpaw-core/`）：

- `crates/qwenpaw-app-server/`：app-server、原前端 HTTP 兼容接口。
- `crates/qwenpaw-core/`、`crates/qwenpaw-storage/`、`crates/qwenpaw-mcp/`：运行时、存储、MCP。
- `crates/qwenpaw-app-server-client/`、`sdk/python/`、`sdk/typescript/`：Rust/Python/TypeScript SDK。
- `crates/qwenpaw-harness/src/codex/`：discovery、control、lifecycle、provider、MCP discovery、projection、runtime pool、sessions、turn。
- 原 Python 行为参考：仓库根 `src/qwenpaw/harnesses/codex/adapter.py`、`harnesses/events.py`、`harnesses/runtime.py`、`harnesses/streaming.py`。

## 最近实现到哪里

1. Discovery / lifecycle / Provider / controls / skills / MCP discovery：独立所有者与关闭边界、状态/模型/登录控制、协议级对照测试。真实 Codex 账号与二进制兼容性尚未验证。
2. Capability projection 与 runtime pool：按能力指纹复用进程，进程代际改变后恢复 skill roots；接收后的生命周期操作不会因调用方取消而放弃清理。完整 capability resolver、真实凭据与策略接线仍缺失。
3. Sessions：`CodexProvider::open_sessions` 管理 `codex_sessions.json`，支持恢复 thread、remote protocol 错误后回退新 thread、原子发布映射、reset/stop/shutdown。单写者是调用方前提，尚未通过跨进程锁强制实现；不保证抵御文件系统并发替换或断电场景。
4. Raw turn：`CodexSessions::start_turn` 保留原输入/模型/推理/sandbox 参数，先订阅再 start，过滤 thread/turn，保留完整远端通知，支持 cancel/Drop、interrupt 应答、EOF、订阅丢失与背压处理。

`CodexTurn::next()` 的 EOF 不代表成功，调用者必须读取 `finish()` 结果。`TurnEnd::Remote` 仍可能包含 failed 状态；`InterruptAcknowledged` 只证明 RPC 应答收到。start 超时且没有 turn ID 时，远端是否已执行仍可能不确定。附件层只投影路径，不读取或授权文件。

**尚未实现**原 HarnessEvent/Chat 转换、审批上下文、同会话 turn/reset/provider 替换互斥、完整历史/命令及 HTTP/Agent backend。不要提前开启后端、删除 409/未实现保护，或将测试组件描述成完整 Chat 功能。
